# Project Setup Guide (Python + Git)

This guide walks through setting up this project from scratch — creating a virtual environment, installing dependencies, and configuring Git — with an explanation of *why* each step matters. Written for beginners.

---

## 1. Prerequisites

Before starting, make sure you have:

- **Python 3.x installed** — check with:
  ```bash
  python --version
  ```
  or on some systems:
  ```bash
  python3 --version
  ```
- **Git installed** — check with:
  ```bash
  git --version
  ```
- **VS Code** (or any editor) with the Python extension installed.

---

## 2. Clone the repository

```bash
git clone https://github.com/devsanjayk/finance-app-api.git
cd finance-app-api
```

**What this does:** downloads the project's code and full Git history to your machine, and moves your terminal into that folder.

---

## 3. Create a virtual environment (venv)

### What is a venv and why do we need it?

A **virtual environment** is an isolated Python installation just for this project. Without it, every package you install goes into your *global* Python — which causes version conflicts when different projects need different versions of the same library (e.g. Project A needs `pandas==1.5`, Project B needs `pandas==2.2`). A venv keeps each project's dependencies separate and self-contained.

### Create it

From the project root folder:

```bash
python -m venv .venv
```

**What this does:** creates a folder named `.venv` containing:
- A private copy of the Python interpreter
- `pip` (the package installer)
- Activation scripts

> ⚠️ Just creating an empty folder called `.venv` does **not** work — it must be generated by the `python -m venv` command above, which populates it with the actual interpreter and scripts.

### Verify it was created correctly

```bash
ls .venv
```

You should see folders like `Scripts` (Windows) or `bin` (macOS/Linux), plus a `pyvenv.cfg` file.

---

## 4. Activate the virtual environment

Activation tells your terminal: *"use the Python and pip inside `.venv`, not the global ones."* The exact command depends on your shell:

| Shell | OS | Command |
|---|---|---|
| Git Bash | Windows | `source .venv/Scripts/activate` |
| PowerShell | Windows | `.venv\Scripts\Activate.ps1` |
| Command Prompt (cmd) | Windows | `.venv\Scripts\activate.bat` |
| bash/zsh | macOS/Linux | `source .venv/bin/activate` |

**How to know it worked:** your terminal prompt will now show `(.venv)` at the start, e.g.:

```
(.venv) sanja@sanju MINGW64 /e/finance-app-api (main)
```

### Common issue: PowerShell blocks the script

If you see *"running scripts is disabled on this system"*, run this once (PowerShell only):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Then try activating again.

### To deactivate later (any shell)

```bash
deactivate
```

---

## 5. Install dependencies from `requirements.txt`

### What is `requirements.txt`?

It's a plain text file listing every Python package the project needs (and optionally, the exact version), so anyone can recreate the same environment with one command — instead of guessing what to install.

### Install everything listed in it

With your venv **activated**:

```bash
pip install -r requirements.txt
```

**What this does:** reads each line in `requirements.txt` and installs that package (and its own sub-dependencies) into `.venv`.

---

## 6. Adding a new package (ongoing workflow)

Whenever you need a new library for the project:

```bash
# 1. Make sure venv is activated
source .venv/Scripts/activate

# 2. Install the package
pip install fastapi

# 3. Update requirements.txt to include it
pip freeze > requirements.txt

# 4. Commit the change
git add requirements.txt
git commit -m "add fastapi dependency"
git push
```

### What does `pip freeze` do?

It lists every package currently installed in the active venv, along with its exact version, e.g.:

```
fastapi==0.115.0
pandas==2.2.0
numpy==1.26.4
```

Redirecting it into `requirements.txt` (`> requirements.txt`) captures a **pinned, reproducible snapshot** — so anyone installing later gets identical versions, avoiding "works on my machine" bugs.

---

## 7. Setting up on a new machine (or for a teammate)

You never share the `.venv` folder itself (it's machine-specific and can be huge). Instead, anyone can rebuild it from `requirements.txt`:

```bash
git clone https://github.com/devsanjayk/finance-app-api.git
cd finance-app-api
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
```

## 8. Git configuration (author identity)

Git records who made each commit using two config values: `user.name` and `user.email`. If these are wrong (e.g. left over from a different laptop/account), your commits will show up under the wrong name on GitHub.

### Set identity for this repo only (recommended if you use this laptop for multiple accounts)

```bash
git config user.name "Sanjay Kumar"
git config user.email "your-personal-email@example.com"
```

### Set identity globally (applies to every repo on this machine)

```bash
git config --global user.name "Sanjay Kumar"
git config --global user.email "your-personal-email@example.com"
```

### Verify it's correct

```bash
git config user.name
git config user.email
```

> Note: this only affects **future** commits. Already-pushed commits keep the old author name unless history is rewritten (an advanced, riskier operation — usually not worth it for minor personal projects).

---

## 9. `.gitignore` — keeping unnecessary files out of Git

Your `.venv` folder and other machine-specific files should **never** be committed — they're large, regenerable, and personal to your machine. Make sure your `.gitignore` file includes:

```
.venv/
__pycache__/
*.pyc
.env
```

**What each line means:**
- `.venv/` — the virtual environment folder (rebuildable via `requirements.txt`)
- `__pycache__/` and `*.pyc` — Python's compiled bytecode cache files, auto-generated, not needed in source control
- `.env` — environment variable files, which often contain secrets/API keys and should never be pushed to a public repo

## 10. Daily workflow summary

```bash
# Start work
source .venv/Scripts/activate
git pull

# ...write code, install packages as needed...

# Save your work
pip freeze > requirements.txt   # only if you installed something new
git add .
git commit -m "describe your change"
git push
```

## Quick troubleshooting reference

| Problem | Likely cause | Fix |
|---|---|---|
| `.venv/Scripts/Activate.ps1: syntax error` | Running a PowerShell script in Git Bash | Use `source .venv/Scripts/activate` instead |
| `running scripts is disabled` | PowerShell execution policy | Run `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` |
| `.venv` folder exists but has nothing in it | Folder was created manually, not via `venv` module | Delete it and run `python -m venv .venv` again |
| Wrong name shows on GitHub commits | Git `user.name`/`user.email` misconfigured | Run the `git config` commands in Section 8 |
| Package installed but "not found" in code | venv not activated when installing, or wrong interpreter selected in VS Code | Activate venv, then `Ctrl+Shift+P → Python: Select Interpreter` and choose the `.venv` one |
